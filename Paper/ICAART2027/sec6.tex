\section{\uppercase{Conclusion}} \label{sec6}
In this study, we proposed a method that adaptively selects RAG configurations based on query characteristics to balance trade-offs between accuracy and computational cost. Specifically, we trained ranking models (RM) over candidate RAG configurations using query features, document features, and configuration parameters to present top-performing candidate configurations. Final configuration selection is performed using a multi-objective score aggregating precision, recall, $F_1$ score, and execution latency via user-defined priority weights. By adjusting these weights, users can flexibly switch operational policies between accuracy-oriented and cost-oriented modes. Experimental evaluations demonstrated that the proposed method significantly improves response accuracy (BERTScore $F_1$ score, EM, Token-level $F_1$ score) and reduces execution latency compared to fixed configurations (Default Setting, Most Frequent Setting) and existing adaptive baselines (Adaptive-RAG), achieving clear Pareto improvements. Furthermore, Wilcoxon signed-rank tests confirmed the statistical significance of our method's superiority over baselines. In top-$K$ user selection evaluations, although cumulative trial execution latency is incurred, response accuracy is further enhanced, and time-oriented selection matches Oracle best time performance. Ablation analysis confirmed that while RAG configuration information forms the foundational baseline for ranking, comprehensively integrating query and document features achieves the highest ranking accuracy (NDCG@1=68.52\%, Hit@5=65.00\%). Feature importance analysis also confirmed that generative models and retrieval strategies dictate macro performance while input data features (cosine similarity, document length) contribute to fine-grained rank decisions.

Future work includes further enhancing RM ranking prediction accuracy and developing an automated priority weight estimation mechanism. Specifically, we aim to design gate networks that automatically infer optimal weight vectors directly from query difficulty and runtime system constraints.
